# Behavior catalog

The rules m2b keeps (B) and the defects a tool like it easily has and m2b must not (X), each with
the reason. The examples use invented data. A test that covers a rule says so in its docstring
(`Covers: B12`), and `scripts/check` lists every rule here that no test names yet.

## Behaviors m2b keeps

| ID | Behavior | Why |
|---|---|---|
| B1 | Capture writes a new file, text byte for byte (typos, spacing kept); one trailing newline added only if missing | the capture is the original; judgment belongs to curation |
| B2 | A name collision draws a new random suffix; an existing file is never overwritten | two captures in the same second |
| B3 | Empty text or no store set up: exit 2; a store folder that is missing: exit 3; either way nothing written, no folder created | a capture must never land in the wrong place |
| B4 | The quiet marker counts only as the exact frontmatter line, never in the body; a client sets it only on its own new file | it silences proactive replay and must not be set by accident |
| B5 | Every proactive replay states its reason ("random pick from May 2026", "touches the open question about the garden shed") | the owner judges whether the replay was worth it |
| B6 | Evicted files are never read; commands list them with the command that fetches them | a read would download or hang |
| B7 | Session-start hooks always exit 0; without a config they print nothing, with a config they print one line when something needs the user | a hook must never block a session, and "could not look" must still show |
| B8 | The distillate is printed up to 8 KB, cut on a character boundary, with a line saying it was cut | bounded context; the cut is visible |
| B9 | The routing rule is printed only together with a distillate | no rule without a brain to route to |
| B11 | The curation nudge only starts the runner detached and returns at once | the session must not wait for curation |
| B12 | A run is due 20 hours after the last successful run or when the inbox holds a visible file (hidden files do not count), unless the backoff after a failed run (1, 4, 20 hours) has not passed | runs when there is work |
| B13 | A failed core step keeps the run due; the last successful run moves only after a run whose core steps all succeeded. A failed add-on step, a failed reading of the sessions (B119), a task for the waiting proposals that could not be brought up to date (B124), or a commit of the run that failed (B141), is reported in the review and leaves the run succeeded | a partial run must be repeated, but an add-on that keeps failing must not hold back the filing of the inbox |
| B14 | Findings that need the owner and failures of a run go into the one review task, with the time of the run; a clean run completes it | one place to look |
| B15 | There is only one review task; it is found by its marker, open or completed, and reopened, not duplicated | a review found by title became two when renamed |
| B16 | Ingest is restart-safe: tasks are created before the move, recorded in frontmatter, and the move into the archive is the last step; a rerun never creates a second task or a second archive file | a crash at any point loses nothing |
| B17 | Ingest never adopts a task by its title; it finds its own tasks by the capture marker in their notes | recurring tasks share titles; adopting by title could swallow a real one |
| B18 | A missing `created` is filled from the file's modification time with offset; a missing `source` from a conforming name, else `cli` | files dropped into the inbox by hand |
| B19 | The month folder follows `created` in UTC, for text and binaries alike | one time base (X5) |
| B20 | A binary bundle gets its sidecar at normalize time (the only moment the original name is known), a reading copy where needed, and the sidecar moves last; a rerun on any member completes the rest | a bundle is never half in the archive |
| B21 | Lint reports schema violations, evicted files, broken links, facts missing from the index, an oversized distillate, orphaned sidecar references, binary volume. `lint fix` removes only verified conflict copies and our own leftover temp files; the lint skill may repair a broken link in `memory/` when exactly one archive file matches | reporting is safe, deleting is not |
| B22 | `[[links]]` point to archive files only, always with extension | links without extension once broke silently |
| B23 | The journal appends completed tasks per month, deduplicated by (task id, completion date), existing bytes kept, curator tasks left out, nothing before `journal_since` | an append-only record of what got done |
| B24 | A tasks or calendar backend that answers with zero lists or zero calendars has failed; it never returns an empty result | without privacy grants, macOS answers empty with exit 0 |
| B25 | Calendar events are deduplicated across accounts by title and start; read-only calendars are read but never offered for writing | the same meeting appears in several accounts |
| B26 | Event creation requires a named, writable calendar and reads the event back before reporting success | an entry in the wrong calendar, or one that was never saved, must not read as done |
| B28 | Worklog: the next period starts at the watermark; a period crossing it is clipped and finishes in the next | no gaps, no double counting |
| B29 | Worklog: only spheres marked billable get booking proposals; the customer list is read only | booking is the owner's act |
| B30 | Band: re-read before every write of a keep or drop; when another session already settled the item, write nothing and say so in the band | a stale "drop" once deleted a candidate the owner had kept |
| B31 | Band: refreshes every 60 seconds and after each turn; findings and candidates capped with "and N more" | the band stays small and current |
| B32 | Follow-up: a task with a due date whose notes name the capture's file name; the capture records the task, or `follow_up:` when the task could not be created yet | done by the model alone, a follow-up takes three steps and one of them gets skipped |
| B33 | A worklog note never names a session the recorder saw for less than 2 minutes | brief focus changes are noise |
| B34 | Harvest writes the capture before deleting the candidate task and recognizes its own earlier captures by `from_candidate` | a crash between the two steps neither loses nor doubles a fact |
| B35 | A candidate equal to an open one or to one dropped within 90 days is refused | the same proposal must not come back daily |
| B36 | A fact file never links the same capture twice, and `facts_filed: true` stops a rerun from filing the capture's facts again | a crash between filing facts and the move must not double them |
| B37 | Setup joins an existing store instead of writing over it, also while its files are still evicted | a second machine must not reset the profile or the distillate |
| B38 | The recorder records nothing when the worklog plugin is no longer installed | uninstalling through `/plugin` must stop recording |
| B39 | On macOS both store backends guard against evicted files; on a folder with only local files the guard changes nothing | Dropbox and OneDrive also keep files on demand; reading one would download it or hang |
| B40 | A fact that stops being true on a known day carries `until: YYYY-MM-DD` in its fact file, a current item ends in `(since YYYY-MM-DD)`, both set when the line is written; lint reports one that is no date | a dated line would otherwise stay in every session after its day, as long as no capture touches it; only the writer knows the date for sure |
| B41 | A curation run finds the facts past their `until` and the current items whose `since` lies more than 30 days back in code; it starts the model only for due facts, allowed to edit the distillate and those fact files alone, and rewrites each so it is true today | a dated fact must not mislead every session after its day, and checking every line at every run would cost a model run for nothing |
| B42 | A current item whose `since` lies more than 30 days back becomes one task "Still current? ..." (never two for the same item); at the next run, ticked keeps it with `since` set to that day, dropped or deleted takes it out of Current, and the task goes after the distillate was written; a question whose item changed meanwhile is closed | whether something is still going on only the owner knows, and a question that is applied twice after a crash must change nothing |
| B43 | `m2b curate --refresh-all` runs once, due or not, and its refresh step also gets the fact files without `until` and the current items without `since`, allowed to edit the distillate, the due fact files and the fact files of its batch, and read `corpus/`; it dates a line only where the evidence names the day, and every other run never sees the undated lines | lines written before dates existed would otherwise never expire, and guessing a date for a lasting fact would make it expire wrongly |
| B44 | Facts under a topic (`### <name> (<word>, <word>)` in the facts section) stay out of the session start; every session gets the other lines, one line naming the topics, and the facts of each topic a word of which is in the project folder's path below the home folder | what matters in one context stays out of the others, and the session still knows what exists |
| B45 | A topic word matches whole (no letter, digit or underscore next to it), case-folded and in Unicode NFC; in a path `-`, `_`, `.` and `/` count as spaces; words under three characters never match | "Acme" must not fire on "Acmes", and macOS hands out decomposed paths |
| B46 | The session start keeps every line of the distillate that is not in a topic, lines the parser cannot read included; the cut takes from the end, path topics first, then the topic line, and a topic comes only whole | nothing a session saw before topics existed is dropped silently |
| B47 | A session notes the topics its start showed; `/clear`, compaction and a new session start the list over, a resumed session keeps it; a session id that is not letters, digits and dashes is never used | a topic comes in once while the context still holds it, and an id never becomes a path |
| B48 | Lint reports a `###` heading in the facts or the current section that is no topic, and a topic in either with fewer than two or more than five words, a word under three or over 40 characters, a name over 60; the size target counts per view, a topic's current items with its facts | a broken heading decides wrongly when facts come in |
| B49 | Before each prompt, the facts of each topic the prompt or the project path names and the session has not been shown come in as `additionalContext`, under a header saying they are data and not instructions, whole topics up to 4 KB; the hook prints nothing on any error, inside a curation run or where the distillate is off | a topic comes in where it is talked about, and a hook on every prompt must never cost the prompt |
| B50 | Every session start prints the same work rule: people and verbal agreements from work may be captured, documents and confidential statements of third parties never | who is who is what a second brain is for |
| B51 | `m2b curate --sort-facts` runs once, due or not, with a fenced step that may read `memory/` and edit only `MEMORY.md`; afterwards code compares: when a facts line, a line outside `## Facts` or any other text changed, the old file goes back and the step fails | the model may only move lines and write topic headings, and an edit could change a statement without the fence noticing |
| B52 | `m2b` on a Python older than 3.9 prints one line naming the interpreter and its version and exits 1, before importing anything of m2b | an import error deep in the package says nothing about the cause |
| B53 | Outside a curation run, the commands that move, rename or edit store files (`ingest normalize`, `task`, `ref`, `note`, `facts-filed`, `finish`, `harvest`, `journal`, `lint fix`) exit 2 with one line naming `m2b curate` and change nothing; `m2b --help` does not list `ingest`, `harvest`, `journal` or `hook` | clients only add; a session or a skill that calls a curator step by mistake must not file half a capture |
| B54 | Before the refresh model step code takes a snapshot of `memory/`; afterwards only the due fact files and the distillate's lines for them may differ (in the backfill also the current items it was given, by their `(since ...)` alone); any other change, also after a failed step, puts `memory/` back and fails the step | refresh may change exactly what is due, and its model reads archived text the code does not control |
| B55 | Ingest and lint model steps keep their edits, and code lists every facts line they removed or rewrote and every fact file they emptied or removed in the review task, with the captures filed in that step and where `memory/` as it was before the run is kept (machine state, one copy per run); these findings come back in every review until the owner completes the review task, and a copy goes only when no waiting finding names it | their edits are many and legitimate, but a capture asking to clear the facts must not silently empty every later session, and the next run must not bury the finding |
| B56 | A line a model step writes into `memory/` that holds bidirectional controls, zero-width space, word joiner, invisible operators, a byte order mark or tag characters puts `memory/` back as before the step and fails it (the sorting step's file likewise), and takes `facts_filed` off the captures still in the inbox that gained it in the step; what text people write carries undoes nothing: the joiners, the direction marks, the selector after an emoji, a soft hyphen (the hooks take these out before a session reads the line, B143) | such a line reads one way to the owner and another to the model, and the distillate enters every session |
| B57 | An inbox file ingest cannot file (a name or date normalize cannot handle, a text that is not UTF-8, a schema-named capture in a subfolder) is noted with its modification time after an ingest step that ran to its end and saw it; while it is unchanged it makes no run due and starts no ingest model step, and every run names it in the review | one export the codec cannot read would otherwise start a model run at every session start, for ever |
| B58 | The questions "Still current?" are kept with the task list they were asked in; a question missing from another list is asked again there, not counted as deleted | after setup switched lists the owner never saw the question, so no item may leave Current for it |
| B59 | A Markdown task file that cannot be read as a task is left out of every list (tasks, harvest, ingest, journal, review), `m2b tasks list` names it on stderr, and lint reports it as an action when Markdown is the backend; while such a file exists, no question, candidate or review task missing from the list counts as deleted by the owner | one hand edit must not stop every task step of every run, nor the review task that would say so, nor be read as the owner's answer |
| B60 | `m2b setup inspect --json` answers a machine without config with `"store": null`, and a store folder that does not exist yet inside one that does with `"store_exists": false`, both exit 0; a folder whose parent is missing too stays unreachable (exit 3) | these are the first two answers the setup skill reads on a new machine, and an error there makes a model stop |
| B61 | Every model step runs fenced: `claude -p` from an empty folder, `--setting-sources project`, `--permission-mode dontAsk`, and either this plugin alone with only the commands and store paths of its step, where a denied call fails the step and becomes a finding, or, for a step that only reads a text and answers, no plugin, no tool (`--tools ""`), no MCP server, no skill, one turn and no session kept on disk, the text on standard input | a model that reads captures must not reach the owner's settings, other plugins or anything outside its step; a model that reads what a person typed has nothing to call at all, and the text is not written a second time under Claude Code's folder |
| B62 | Only the machine `store.json` names curates; any other refuses into its local log and exits 0 | iCloud gives no lock shared between machines, so two curators would file the same inbox twice |
| B63 | One run per machine, held by a lock that every child of the run keeps; after a failed run the next attempt waits 1, then 4, then 20 hours, even over a full inbox; a run in which only steps failed that leave it succeeded (B13) starts no wait | a failure that does not clear by itself must cost one attempt, not one per session |
| B64 | An add-on that is off runs no curation step, prints nothing at session start and draws nothing | an add-on must cost nothing until its own setup turns it on |
| B65 | `m2b distillate off` in a folder keeps the distillate, the routing rule and topic facts out of every session there and below, on this machine | a screen share or a customer's repository must not show the owner's facts |
| B66 | Setup run again with the same answers changes no file | setup is the way to repair a machine, so running it twice must be safe |
| B67 | A curation run starts a model only for a step with something to read: ingest for captures, refresh for a fact past its day, lint for a broken memory link with one candidate | a run with nothing to file must cost no model run |
| B68 | `m2b search --any` searches each term as a phrase of its own and reports every line that holds one of them once; `--word` holds for each term; without `--any` several words are one phrase | a word and its translation in one search, so a note in the other language the owner writes in is found |
| B69 | `format` in `store.json` counts the rules for curated content; this m2b knows one format more than it has migrations, numbered from 2; a curation run on the curating machine first runs each migration above the store's format, in order, each as a step `migrate-<format>`, and writes the new `format` after each | content already in a store follows a new rule without the owner running anything |
| B70 | A migration that fails, or changes `memory/` beyond what its code check allows, puts `memory/` back, leaves `format` as it was and ends the run with the review, which names the step; an m2b that knows an older format does not curate the store and changes nothing | later steps follow rules the store does not hold yet, and an older curator would write under old ones |
| B71 | `m2b capture` writes into a store of a newer format, follow-up task included; a `store.json` that cannot be read is refused before anything is written | the inbox contract does not change with the format, so a second machine on an older m2b keeps capturing |
| B72 | `m2b doctor` and `m2b status` give the store's format against this m2b: `current`, `newer` with "update m2b on this machine" (a problem for doctor's exit code), or `migrates` naming the curating machine whose next run migrates it | after an update the owner sees which machine is behind, and why the next run takes longer |
| B73 | This m2b knows store format 3; its two migrations, to formats 2 and 3, change nothing in `memory/` and fail if anything changed, so an older store only gets its new number, one step per format | format 2 adds earlier values, which an m2b that knows format 1 would drop while curating; format 3 adds topics under current, whose headings an m2b that knows format 2 reports as errors |
| B74 | Lint reports a line under a fact file's `## Earlier` that is not `- <statement> (until YYYY-MM-DD)` with a real day, as an action | an earlier value without the day it ended says nothing about when it held |
| B75 | A capture whose file cannot be written (no write permission, a full or read-only disk) exits 4 with one line saying "the capture was not saved" and the folder, writes no note and removes the follow-up task it created for it; a task it cannot remove is named in that line, and the capture skill decides by that line, not by the exit code | otherwise the skill tells the owner the note is kept, and a task points to a note that does not exist |
| B76 | A model step stopped by SIGTERM still has `memory/` checked as in B54 to B56 and put back before the runner exits, and a check that fails does not keep it from stopping; a run that never stored its changes leaves its copy of `memory/` marked, and the next run on the machine that gets past preflight compares `memory/` with the oldest marked copy and lists a line that hides text and every facts line removed or rewritten in the review, which keeps the copy | a stopped runner would otherwise leave such a line in every later session, and the next run would prune the only evidence |
| B77 | A `store.json` with a key that its own format does not have is refused, also when this m2b knows the key from a later format; every key belongs to the format it came with, so a new key raises the format, and an m2b that knows the format before reads the store as newer (B71) | a typo in a key is caught, and a key added later does not stop capture on every machine with an older m2b |
| B78 | The journal fetches evicted month files once, together; a month file still evicted after that gets nothing in this run, is named in the review with the command that downloads it, and the other months are written | completed tasks reach back to `journal_since`, so one old month in the cloud would otherwise fail every run |
| B79 | A capture that will not download within the fetch timeout does not stop the curation run: it waits in the inbox, with every file of its bundle, ingest starts no model step for it alone, the run record names it, and while it stays evicted and unchanged it makes no run due by itself; each file asked for gets its share of the fetch time; `m2b capture` first fetches an evicted `store.json` and, when it stays evicted, refuses with exit 3 and the command that downloads it | one file iCloud is slow to bring stops neither curation nor capture on a second machine |
| B80 | `m2b todos` names each Markdown task file it cannot read as a task, with its path and the reason, never says "No open tasks." beside one, and exits 1; JSON carries them as `unreadable`, and the todos skill says it could not look at them; a task file without read permission or not downloaded ends the command with exit 3 and its path | a list missing a task must not read as everything that is open |
| B81 | Setup for a machine that is to curate refuses a store path holding a character the rules that fence a model step cannot name (`, ( ) [ ] * ?`, a backslash, a line break) with one line saying why, before anything is written, and `m2b curate take-over` and `m2b config set` (for `store.path` or a whole `store` section, judged by the store at the new path) refuse such a path likewise; `m2b setup inspect` names it in `store_path_problem` before the interview; `m2b doctor` on the curating machine names such a path as a problem; a machine that only captures may use one; the characters are listed in one place, which the curation run checks too | every curation run would refuse that store, and the owner would only learn it from a failed run |
| B82 | `STORE.md` gives each integration (a program outside the marketplace that writes into the store) its own state folder `state/integrations/<name>/`, and the curation run never asks for anything under it | an integration's state is its own; reading it would download files the run does not need and let a foreign program steer the curator |
| B83 | A `config.json` that names an add-on m2b no longer has (`herdr`, `backup`, and `band`, which became part of the core) loads as before and that entry is ignored with its settings; `m2b addons on` and `m2b config set addons.<it>...` refuse it with one line saying why it was removed; `m2b addons off` removes the entry and changes nothing else; `m2b curate take-over` does not list it | an update must not break a working machine over a setting nobody reads, and the owner needs a way to tidy it up that says why |
| B84 | Worklog: focus counts up to 10 minutes after each event of the focused workspace, never kept alive by events of another; an agent counts up to 30 minutes past its last sign of life (an event of its pane or a stamp of its session's transcript), so a silent stretch longer than that counts 30 minutes, and an agent still writing its transcript at the cut counts up to the cut | herdr sends nothing while the machine sleeps or after it quit, and no event says the owner left; without these bounds a night or another workspace's agent becomes a booking proposal |
| B85 | Worklog: the same minutes never land in two sessions. Workspaces on one folder are one session, also after the workspace is closed and opened again under a new id; a transcript belongs to the workspace whose folder or pane folder holds it, preferring one open while it was written, then one whose own folder holds it, then the closest folder | a reopened workspace counted one evening twice in a real ledger, and each proposal would have been booked twice |
| B86 | Worklog: every ledger span carries `minutes`, the work inside it, and `minutes_present`, the part with its workspace in focus; both reach the CSV and the XLSX, and a ledger written before the second column still loads and exports with that cell empty | whether an agent's own time is billable depends on the agreement, so the owner needs both numbers |
| B87 | Worklog: a period overlapping one the ledger holds is refused, before the model step and before anything is written, with a message naming the held period (and a span of the same session when there is one); the messages about an unreadable watermark or unfinished worklog name `m2b-worklog state`, which shows the watermark (or where a missing one belongs), an unfinished worklog and the last period, and never advise deleting a file; a run reads only recorder files written from three days before its period, keeping the focus still in force from before | a reset watermark would otherwise book the same days twice, also under another session key, and the history would make every run slower |
| B88 | Worklog: the recorder writes a sign of life at herdr's start and at each tick of an operating-system timer (launchd on macOS, systemd on Linux, every five minutes) while recording is allowed and a herdr socket its events came from answers. `recorder install` links the recorder again when the version noted beside its copy at the last link differs from the copy's, or no version is noted (herdr's plugin list shows the manifest as it is now, not what herdr registered), and starts a timer that is not loaded; a start that fails leaves no timer files. The session-start refresh links again until a link of the copy's version succeeded, and puts the timer in place while the machine records, starting no process when it is. `recorder remove` takes out the timer and the copy before it asks herdr, and forgets the first tick. Tests and e2e never reach the real `launchctl` or `systemctl` | herdr has no timer for plugins, forbids a startup hook to leave a process behind, and reads a plugin's startup command only when linking; without signs of life silence cannot tell an idle evening from a herdr that was not running |
| B89 | Worklog: from the timer's first tick on, a silence of more than 10 minutes without any sign of life or event is in the facts as `not_recorded`, from five minutes after the last sign to the next, and in the note under "Not recorded", with both dates when it crosses midnight; a recorder without the timer claims nothing | a gap in the recording read as a time without work, also to the model that judges the day |
| B90 | Worklog: setup first runs `m2b-worklog recorder check`, which says whether herdr is installed, at least 0.9.0 (the version the recorder's manifest asks for) and running, and stops before any question when it is not | the setup asked for spheres and customers before it found out that herdr was missing |
| B91 | Band: part of the core, with no switch: it draws and keeps the status line wherever the machine config and the launcher exist, asks only `m2b band` and `m2b tasks`, and before that draws nothing, clears the status line and asks m2b nothing; a store that cannot be read shows its error line; the status line carries no prefix of its own | it is where the core speaks to the owner, and without it the review task was never shown; Claude Code already names the plugin in front of the line |
| B92 | Band: each session start writes `band-seen.json` in machine state, the core's launcher hook writes `session-seen.json`, and `m2b doctor` reports `band: seen` when the latest session ran the band, else `not seen` naming mods off (that session ran m2b's hooks only) or all plugin hooks off (none since setup), with local times; neither counts as a problem | the core cannot ask Claude Code whether it loaded the mod, and a note that never goes stale would hide a band that stopped |
| B93 | Band: one refresh is one `m2b` call, `m2b band --json`, which reaches and reads the task list once (two Apple Reminders calls) and answers the open candidates, questions and review tasks by marker together with the answer of `m2b status --json`, whose check of the task list reuses that one look and whose calendar probe keeps to 10 seconds; a list that is reached but cannot be read is `tasks.error` beside a status that still answers; the look before a keep or drop is `m2b band --json --tasks-only`; sessions share the answer for 55 seconds | four `m2b` calls per refresh in every open session, with the same Reminders list fetched three times, and a slow calendar could have kept the band's rows from ever arriving |
| B94 | Band: keep and drop write nothing for 5 seconds, while the row offers only undo; undo forgets the press, and a crash, a closed session or a reload of the mod in those seconds writes nothing; the row then stays locked until the reload after the write has landed, also across a reload of the mod; the task id goes to `m2b tasks complete` and `drop` after `--` | a mis-click with the mouse must not cost a candidate that does not come back for 90 days, a second press must not meet the old row, and an id that starts with a dash is not an option |
| B95 | Band: every text from the store and from `m2b` is drawn as one plain line, escape sequences and control characters removed, line breaks and tabs as spaces; a failure inside a timer or a launcher that cannot be started leaves the status line at `could not look` and the band at one error line; however many turns end while `m2b` is slow, at most one reload waits; a shared answer of the wrong shape or stamped in the future is loaded again; `M2B_HOME` with a leading `~` resolves under `HOME`; a reload under way when m2b stops being set up draws nothing; a write that never returns frees its row after 3 minutes; the core keeps the machine state folder, where the shared answer lies, readable by its owner only | Claude Code refuses a drawing with a control character and then shows none of the band, an unhandled rejection in a timer left an old state on the status line, and forced reloads queued up behind a slow backend |
| B96 | Band: `m2b band --json` names the installed core's `version`; when the session's band comes from an older version, by `MAJOR.MINOR.PATCH`, the band shows one line naming `/reload-plugins`; a newer band, as from a checkout, says nothing | a session started before an update keeps its old band, which can call commands the installed core no longer has, and nothing said so |
| B97 | Worklog: from a transcript go prompts of at most 240 characters, without the blocks Claude Code adds (`<system-reminder>` and the like) and without the summary written after a context cut, and the last 500 characters of the last answer; both are redacted first: the value after password, `pw`, secret, token and their kin, also with up to four words between ("the password for the db is hunter2"), a credential after `Bearer` or `Basic`, long mixed tokens and base64 keys with `/` and `+`, while paths stay as written | the model sees only what it needs to judge a session, a question to the owner stands at the end of an answer, and a reminder in front of a prompt used up its 240 characters; pattern redaction stays incomplete, and the page says so |

Without a `.git` in the store folder, without git on the machine (on macOS: without the developer tools, whose stand-in for git is never started), or with `curation.git_commit` set to `false` in the machine config, nothing is done and nothing is reported | a curator that rewrites memory by itself needs a net the owner can pull: `git revert` takes one run back, and whoever keeps no repository must not notice any of it |
| B140 | The commit of a run (B139) is m2b's own and touches nothing else of the repository: author and committer are `m2b <m2b@localhost>`, the message names the run's start and how its steps ended; m2b creates no repository, writes no git configuration, never pushes, runs no hook and signs nothing, and of the index it brings only the committed paths up to date. It commits onto HEAD as it is: a HEAD that moved while it worked, or a merge, rebase, cherry-pick, revert or bisect the owner has not finished, means no commit | the repository is the owner's; a run in the background has nobody to answer a prompt, and its commits must be told apart from the owner's own work |
| B141 | A commit of a run (B139) that fails leaves the run as it ended: the failure is the failed step `commit` in the review task and the run record, and no wait starts for it (B13). git is handed only files that are downloaded (B6): a changed file that is evicted is left out, an evicted `.gitignore` or `.gitattributes` on the way to a changed file stops the commit and names the command that fetches it, and so does an evicted `.git` | the commit is the net, not the work: it must never cost a run, and never be the reason a file is downloaded |
| B142 | `m2b search` answers the hits of a file together, in line order, and the files in the order of the answer, whatever order they were read in: `memory/` first, there `MEMORY.md` before the other files by path; then `corpus/`, then `inbox/`, in both the newest note first by the time in its name, never by the time of the file; a month's journal comes after the notes of its month and before older notes; a file whose name carries no time comes after every dated one of `corpus/` or of `inbox/`, by path. The lists of files not searched keep their order | the `/m2b-search` pane and the model's tool (B104) show the first 100 hits, and those should be what curation wrote and what is newest, not the oldest notes; in a synced folder the time of a file is when it arrived on this machine |
| B143 | The session-start hook, the prompt hook and the mod's tools hand a model text from the store without the characters that draw nothing: what Unicode calls default ignorable (soft hyphen, fillers, direction marks and bidirectional controls, zero-width space, word joiner, invisible operators, variation selectors, byte order mark, tag characters), without the zero-width joiner and non-joiner, which emoji and several scripts need. The session-start hook takes them out of the distillate, the prompt hook out of a topic's facts (B49) and the mod out of what its tools answer (B104); `m2b search` in a shell prints a hit as it is stored. The core and the mod keep the same table, and every character that undoes a step (B56) is in it | a model does not draw, so it loses nothing, and a character nobody sees can carry text or bytes; with a list each, the core let through what the mod removed: variation selectors, the soft hyphen, fillers |
| B144 | Why a model step failed over what it did to `memory/` (B54, B56, B76) is said without any text of `memory/`: a line with a character that hides or reorders text by its file, its line number and the characters' code points; a line the refresh step may not touch as removed, changed or added by its line number in the distillate as it was before the step, which is how the file is again. A file the step added is not named, only one that was there before it. The session start prints each of its notices without the characters that draw nothing (B143) | the reason goes into the run record, and the session start prints it as m2b's own notice, above the line that marks the distillate as data; a quoted line, or a file name the model chose, put what a capture made the model write into every session in m2b's voice |
| B145 | A curation run started in the background (B11, `m2b curate --detach`) writes its standard error to `detached-run.err` in machine state, emptied at each such start and readable by the owner alone; its standard output is discarded, and a file that cannot be opened keeps no run from starting | a run that died before it could write a run record or a line of the run log left its reason nowhere |
| B146 | `m2b doctor` starts the plugin's `bin/m2b-prompt-hook` with `--check`, within the seconds `hooks/hooks.json` gives the hook, and reports `prompt-hook: answers` with the hook's line. Asked so, the hook reads what a prompt makes it read (machine config, store, distillate), notes no topic as shown, prints one line and exits 1 with the reason it would otherwise swallow; a store without a distillate is no failure. `does not answer` (with that reason, or when the hook is slower than allowed) and `missing` (the plugin's hooks do not name the command, or it cannot be started) count as problems | the hook prints nothing on any error (B49), so one that never works looked the same as a prompt that named no topic |
