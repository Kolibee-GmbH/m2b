# Behavior: the worklog add-on

The rules about the worklog add-on. A test in the add-on's own suite,
`plugins/m2b/tests/addons/worklog/`, names each of them.

It is one of the four parts of the [behavior catalog](../behavior.md), which says what stands where.

## Behaviors m2b keeps

| ID | Behavior | Why |
|---|---|---|
| B28 | Worklog: the next period starts at the watermark; a period crossing it is clipped and finishes in the next | no gaps, no double counting |
| B29 | Worklog: only spheres marked billable get booking proposals; the customer list is read only | booking is the owner's act |
| B33 | A worklog note never names a session the recorder saw for less than 2 minutes | brief focus changes are noise |
| B38 | The recorder records nothing when the worklog plugin is no longer installed | uninstalling through `/plugin` must stop recording |
| B84 | Worklog: focus counts up to 10 minutes after each event of the focused workspace, never kept alive by events of another; an agent counts up to 30 minutes past its last sign of life (an event of its pane or a stamp of its session's transcript), so a silent stretch longer than that counts 30 minutes, and an agent still writing its transcript at the cut counts up to the cut | herdr sends nothing while the machine sleeps or after it quit, and no event says the owner left; without these bounds a night or another workspace's agent becomes a booking proposal |
| B85 | Worklog: the same minutes never land in two sessions. Workspaces on one folder are one session, also after the workspace is closed and opened again under a new id; a transcript belongs to the workspace whose folder or pane folder holds it, preferring one open while it was written, then one whose own folder holds it, then the closest folder | a reopened workspace counted one evening twice in a real ledger, and each proposal would have been booked twice |
| B86 | Worklog: every ledger span carries `minutes`, the work inside it, and `minutes_present`, the part with its workspace in focus; both reach the CSV and the XLSX, and a ledger written before the second column still loads and exports with that cell empty | whether an agent's own time is billable depends on the agreement, so the owner needs both numbers |
| B87 | Worklog: a period overlapping one the ledger holds is refused, before the model step and before anything is written, with a message naming the held period (and a span of the same session when there is one); the messages about an unreadable watermark or unfinished worklog name `m2b-worklog state`, which shows the watermark (or where a missing one belongs), an unfinished worklog and the last period, and never advise deleting a file; a run reads only recorder files written from three days before its period, keeping the focus still in force from before | a reset watermark would otherwise book the same days twice, also under another session key, and the history would make every run slower |
| B88 | Worklog: the recorder writes a sign of life at herdr's start and at each tick of an operating-system timer (launchd on macOS, systemd on Linux, every five minutes) while recording is allowed and a herdr socket its events came from answers. `recorder install` links the recorder again when the version noted beside its copy at the last link differs from the copy's, or no version is noted (herdr's plugin list shows the manifest as it is now, not what herdr registered), and starts a timer that is not loaded; a start that fails leaves no timer files. The session-start refresh links again until a link of the copy's version succeeded, and puts the timer in place while the machine records, starting no process when it is. `recorder remove` takes out the timer and the copy before it asks herdr, and forgets the first tick. Tests and e2e never reach the real `launchctl` or `systemctl` | herdr has no timer for plugins, forbids a startup hook to leave a process behind, and reads a plugin's startup command only when linking; without signs of life silence cannot tell an idle evening from a herdr that was not running |
| B89 | Worklog: from the timer's first tick on, a silence of more than 10 minutes without any sign of life or event is in the facts as `not_recorded`, from five minutes after the last sign to the next, and in the note under "Not recorded", with both dates when it crosses midnight; a recorder without the timer claims nothing | a gap in the recording read as a time without work, also to the model that judges the day |
| B90 | Worklog: setup first runs `m2b-worklog recorder check`, which says whether herdr is installed, at least 0.9.0 (the version the recorder's manifest asks for) and running, and stops before any question when it is not | the setup asked for spheres and customers before it found out that herdr was missing |
| B97 | Worklog: from a transcript go prompts of at most 240 characters, without the blocks Claude Code adds (`<system-reminder>` and the like) and without the summary written after a context cut, and the last 500 characters of the last answer; both are redacted first: the value after password, `pw`, secret, token and their kin, also with up to four words between ("the password for the db is hunter2"), a credential after `Bearer` or `Basic`, long mixed tokens and base64 keys with `/` and `+`, while paths stay as written | the model sees only what it needs to judge a session, a question to the owner stands at the end of an answer, and a reminder in front of a prompt used up its 240 characters; pattern redaction stays incomplete, and the page says so |
| B98 | Worklog: every time of the facts and the note is in the machine's local time in the offset of its own day; when a note's blocks fall on more than one date each block carries its date, and one that ends on the next date shows that date at its end; a capture stamped with `Z` counts also on Python 3.9 and 3.10 | a period across a change of summer time put the other day an hour off, a catch-up note put times of different days side by side, and captures stamped in UTC were silently left out on older Python |
| B99 | Worklog: the model writes its verdict to `verdict-draft.json` in the run folder and `m2b-worklog verdict` reads it from there, so a session key with an apostrophe is handed in as it is; a verdict with a line break in a topic, detail, note, project or activity is refused with its place; a CSV cell that starts with `=`, `+`, `-`, `@`, a tab or a carriage return gets a leading apostrophe | a folder like `Bob's project` could not be quoted in a shell argument and failed the step on every run, a line break started a heading of its own in the note, and a topic could run as a formula in a spreadsheet |
| B107 | Worklog: an unfinished worklog is carried out only when its note's name is one the worklog gives a note, the period's end in UTC, `worklog` and four hex characters (`20260314T170000Z-worklog-1a2b.md`); with any other name, a path with a folder or an absolute one among them, `intent.json` counts as unreadable, nothing is written, and the message does not repeat the name | the name becomes a path below `inbox/`, and `intent.json` lies in the synced store: whoever can write there would otherwise create a file anywhere on the curating machine |
| B110 | Worklog: redaction also takes the value of an assignment whose name holds password, secret, token, a kind of key or their kin (`PGPASSWORD=`, `SECRET_KEY:`, `secretKey:`, `AccountKey=`, `aws_secret_access_key =`, `pass:`), the value standing on the name's line and going whole up to the next space; the password in a URL, also one with `@` in it (`scheme://user:[removed]@host`); the password after `-u` or `--user` with `name:`, also written `-uname:`; and an AWS access key id. The name and the user stay. A commit's subject is redacted like a prompt. What only looks like one stays: a URL without a password, `git@host:owner/repo.git`, `git push -u origin HEAD:main`, `docker run -u 1000:1000`, `secretary: Dana`, `tokenizer=bert` | credentials are typed into prompts and commit subjects the way tools and environments write them, where no word such as password stands alone before the value; a commit subject reaches the note and the archive as written |
| B111 | Worklog: what ran in a folder at or below one the profile's `worklog_leave_out.path_under` names is in no worklog: a session there is not in the facts for the model, the note or the ledger, a transcript from there reaches no other session either, and a commit made in such a session is shown by no other checkout of its repository. The folder counts as recorded, also when it is gone. The profile checks the folders like a sphere's and is written as version 2 exactly once it holds the setting, which an m2b from before reads without it and does not write | work under a confidentiality agreement must not reach the store at all, where redaction by pattern is not enough; a worktree is often removed before the day's worklog runs; an m2b from before refuses a version 1 profile with a key it does not know and would stop curating |
| B129 | Worklog: it proposes nothing for memory and adds no task. The verdict holds the sessions only, one that names candidates is refused with its place like any part the verdict does not have, the note has no part for them, and a worklog run calls no task command of the core | what belongs in memory is proposed from what the person typed, by the reading of the sessions (B115), which shows their own words beside each proposal and files nothing before a keep; the worklog proposed from prompts cut at 240 characters, at most three a day, each as a task of its own |
| B130 | Worklog: a prompt Claude Code marks as sent by another sender than the person (a plugin, a finished task, another session) is no prompt in the facts, and its time still counts as a sign of work; a prompt without the mark, which an older Claude Code writes, and a suggested prompt the person accepted count as theirs. A session only another sender prompted is named like one without a prompt: with a commit, an agent still working or waiting, or 15 minutes of work | a plugin that drives a session sends a task every round, which filled the blocks' prompts and made each such session count as prompted by the owner; the worklog asks what a session was about, so there a prompt too many costs less than a session without any, and an unmarked prompt is not left out as it is where memory is proposed (B112) |
| B135 | Worklog: each file it writes into the store (the day's note, `intent.json`, `ledger.json`, `ledger.csv`, `ledger.xlsx`, `watermark.json`) arrives whole, through the core's own code and by its rule (X22): the temporary file is in machine state, where the core clears what a crash left, and a hidden one stands in the target folder only when the rename would cross volumes. A worklog broken off at the last step of a write leaves the files of the store as they were before that write, and the rerun writes the piece (B28). Whether a file is evicted the worklog asks the core's guard (B39) | a sync service uploads whatever appears in the store's folder, a temporary file and a leftover included; and what is known about a synced folder is kept once, in the core |
| B153 | Worklog: what ran in a folder whose repository has a remote the profile's `worklog_leave_out.git_remote_contains` names is in no worklog, like work in a folder left out (B111), also when the folder is gone by the time the worklog runs. Known of a folder are the remotes noted at a session start (B151) and those git names there now, every remote and not only `origin`, compared as in B152. Work in a folder of which neither says anything is left out too while the profile names a remote, and the facts and the note say under what could not be read in how many folders that was, naming none. The profile takes the parts beside the folders in version 2 and refuses an empty one. A sphere's `git_remote_contains` is compared the same way | the owner's sessions run in worktrees outside the clone's folder, and a remote names them all; a worktree is often removed before the day's worklog runs, and a git that does not answer names nothing: work that cannot be shown to be other work must not reach the store, and the owner must see that something was left out |

## Defects m2b does not have

| ID | Defect | In the product |
|---|---|---|
| X17 | The worklog was one 1,570-line module with untyped German keys between its stages | a package per stage, typed models, published JSON schemas for facts and verdict |
| X19 | Worklog file names in local time could collide and misorder | the watermark is data in `state/addons/worklog/` |
| X20 | Git and herdr failures read as "no commits" and "no sessions" | reported as "could not read" in the worklog note |
