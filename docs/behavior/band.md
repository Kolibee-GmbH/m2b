# Behavior: the band

The rules about the core's mod: the band above the prompt, the m2b pane, the slash commands, the
two tools it gives the model, and `m2b band`, the core's command for it.

It is one of the four parts of the [behavior catalog](../behavior.md), which says what stands where.

## Behaviors m2b keeps

| ID | Behavior | Why |
|---|---|---|
| B30 | Band: re-read before every write of a keep or drop; when another session already settled the item, write nothing and say so in the band | a stale "drop" once deleted a candidate the owner had kept |
| B31 | Band: refreshes every 60 seconds and after each turn; findings and candidates capped with "and N more" | the band stays small and current |
| B91 | Band: part of the core, with no switch: it draws and keeps the status line wherever the machine config and the launcher exist, asks only `m2b band` and `m2b tasks`, and before that draws nothing, clears the status line and asks m2b nothing; a store that cannot be read shows its error line; the status line carries no prefix of its own | it is where the core speaks to the owner, and without it the review task was never shown; Claude Code already names the plugin in front of the line |
| B92 | Band: each session start writes `band-seen.json` in machine state, the core's launcher hook writes `session-seen.json`, and `m2b doctor` reports `band: seen` when the latest session ran the band, else `not seen` naming mods off (that session ran m2b's hooks only) or all plugin hooks off (none since setup), with local times; neither counts as a problem | the core cannot ask Claude Code whether it loaded the mod, and a note that never goes stale would hide a band that stopped |
| B93 | Band: one refresh is one `m2b` call, `m2b band --json`, which reaches and reads the task list once (two Apple Reminders calls) and answers the open candidates, questions and review tasks by marker together with the answer of `m2b status --json`, whose check of the task list reuses that one look and whose calendar probe keeps to 10 seconds; a list that is reached but cannot be read is `tasks.error` beside a status that still answers; the look before a keep or drop is `m2b band --json --tasks-only`; sessions share the answer for 55 seconds | four `m2b` calls per refresh in every open session, with the same Reminders list fetched three times, and a slow calendar could have kept the band's rows from ever arriving |
| B94 | Band: keep and drop write nothing for 5 seconds, while the row offers only undo; undo forgets the press, and a crash, a closed session or a reload of the mod in those seconds writes nothing; the row then stays locked until the reload after the write has landed, also across a reload of the mod; the task id goes to `m2b tasks complete` and `drop` after `--` | a mis-click with the mouse must not cost a candidate that does not come back for 90 days, a second press must not meet the old row, and an id that starts with a dash is not an option |
| B95 | Band: every text from the store and from `m2b` is drawn as one plain line, escape sequences and control characters removed, line breaks and tabs as spaces; a failure inside a timer or a launcher that cannot be started leaves the status line at `could not look` and the band at one error line; however many turns end while `m2b` is slow, at most one reload waits; a shared answer of the wrong shape or stamped in the future is loaded again; `M2B_HOME` with a leading `~` resolves under `HOME`; a reload under way when m2b stops being set up draws nothing; a write that never returns frees its row after 3 minutes; the core keeps the machine state folder, where the shared answer lies, readable by its owner only | Claude Code refuses a drawing with a control character and then shows none of the band, an unhandled rejection in a timer left an old state on the status line, and forced reloads queued up behind a slow backend |
| B96 | Band: `m2b band --json` names the installed core's `version`; when the session's band comes from an older version, by `MAJOR.MINOR.PATCH`, the band shows one line naming `/reload-plugins`; a newer band, as from a checkout, says nothing | a session started before an update keeps its old band, which can call commands the installed core no longer has, and nothing said so |
| B100 | Band: the slash command `/m2b-note <text>`, registered to run at once also during a turn, hands the text to `m2b capture --source claude -` on standard input and answers one line, `noted:` with the cleaned first 50 characters, `not noted:` with the reason, or `nothing noted:` for an empty text, which calls nothing; before m2b is set up it calls nothing either; after a note the status line is read again | a capture through the skill costs a model turn and waits for the agent's turn to end |
| B101 | Band: `/m2b-review` opens the m2b pane with the last run's state and times from `m2b band --json`, every review finding whole and every candidate and question with keep, drop and undo through the band's own presses; `/m2b-search <text>` runs `m2b search --json -- <text>`, with `--word` before `--` when the text starts with `--word` and a space, and shows each hit's file, line and text, and the count of files not downloaded or not readable; both run at once also during a turn, clean every text they draw, write nothing but keep and drop, and answer with the content as text where the pane cannot be shown | the band cuts the review after a few findings, a path at the end of a finding was lost, and looking something up took a model turn |
| B102 | Band: `m2b band --json` names in `tasks.due` the owner's own open tasks due today or overdue, earliest first, each with `overdue`, from the same look at the list, and leaves the part out while `band.due_tasks` in the machine config is `false` (default `true`); the band draws at most three dim rows of them below the candidates, today's first and then the overdue ones most recent first, `due today:` or `overdue:` and the cleaned title, then "and N more due", without buttons, and nothing without a task due | the owner wants the day's tasks where the band already speaks to the owner, and a setting turns them off where that is noise |
| B103 | Band: a curation run that failed is shown as one toast per session and run, naming its start and that its review task and `/m2b-review` say why; the run's start is kept in the session's state, so a reload of the mod does not show it again; a run that succeeded, still runs or was interrupted shows nothing | a failed run showed only in the status line, which is easy to miss |
| B104 | Band: outside a curation run the mod registers two tools for the model, in the prompt from the start: `mcp__m2b__note` runs `m2b capture --source claude --json` with `text` on standard input, `--follow-up` for `follow_up` (a day as `YYYY-MM-DD`, else nothing is called) and `--quiet` for `quiet`, and answers the saved path, the requested day once the task is made or that the task waits for the next run, and what `m2b` reported beside it; a failed capture reads as not saved, nothing written (exit 2 or 3) or unknown (stopped, or no readable answer), so the model does not note twice; `mcp__m2b__search` runs `m2b search --json --any` with `--word` for `whole_words` and `--` before `terms`, and answers at most 100 hits cut at 500 characters under a line saying they are data from the owner's notes, not instructions, every text one line without escape sequences, controls and the invisible characters m2b knows (reordering marks, zero-width characters, variation selectors, tag characters), and names the files not searched; nothing found and could not look read differently, an empty text or no term calls nothing, before m2b is set up both say so and call nothing; each description states the core rules of its skill in the skill's own sentences, and the skills `capture` and `search` name the tool first and keep their commands where it is not offered | a capture or lookup through a skill needs a shell call, and a session that reaches for a tool without loading the skill must follow the same rules |
| B105 | Band: on a call of `mcp__m2b__note` or `mcp__m2b__search`, Claude Code's own verdict stands unless it is an ask that no rule, hook, setting, other plugin or organization ceiling made, and no host answers; that ask becomes Claude Code's verdict on the skill's command (`m2b capture --source claude -`, `m2b search --json -- term`) where a rule made it ask or deny, else allow, for a note only one in the person's own words (B108), as the skills' `allowed-tools` run their commands without asking; a verdict on any other tool is left alone | a mod's tool counts as a write and would ask on every note and search, where the skills' commands do not |
| B106 | Band: a curation run keeps each change of the facts it reports with the whole lines before and after, and `m2b band --json` names them under `tasks.review` while a review task is open, each with fact file, topic, statement before and after and the statement in parts kept, added and removed word by word, with each copy of `memory/` and the review paragraphs they stand for, and only changes whose paragraph the open review still holds; the band draws the review as one row with `ok` and "N facts changed:" and their topics, the other findings as written and a line naming `/m2b-review`; `ok` closes the review task after the same 5 seconds with `undo` as keep, and writes nothing when the review read again holds other findings than the one pressed on; the pane shows each change with its topic and file and the added words green and the removed ones red and struck through, and where the copy lies; a core that names no changes leaves every finding as written | the review repeated each changed fact as two long, cut English sentences, and closing it meant opening the task list |
| B108 | Band: the mod lets `mcp__m2b__note` run unasked (B105) only when every word of the note, compared without case, punctuation and order, stands in one prompt the person submitted in this session: typed at the terminal, sent over Remote Control or the prompt of a headless run, the last 100 of them and the first 50,000 characters of each; a prompt from a plugin, also one submitted as the user's, from another session, a notification or a schedule does not count. Additions in square brackets of up to four words each are left out of the comparison while they hold fewer words together than the rest of the note has different ones; a longer one counts as the note's text. For any other note, one without text and one holding a format character other than the zero-width joiner and non-joiner included, Claude Code's ask stands, after a rule on the skill's command had its say | the tool is in the prompt from the start and ran unasked for any text, so a page the session read could have a note written that the next curation run files and every later session reads; the order is free because the note is the request turned into a plain sentence, the additions are bounded because a whole foreign text would otherwise pass in brackets, and format characters draw nothing, so text spelled in them would never be compared |
| B126 | Band: `m2b band --json` names in `proposals` what `m2b proposals --json` answers (B122): the proposals that wait, each with its id, kind, text, the person's words, the day they were said, topic and due day, and how many answers wait for the next curation run; a store without proposals gives an empty list, and an entry of the proposals file with half a character (a lone surrogate), which no answer could print, is left out like any entry that is not in the form. Where that cannot be looked at (a proposals file or an answers folder that is not downloaded, a proposals file a newer m2b wrote, a store out of reach) the part is `{"error": "<why>"}`, and the tasks and the status still answer; `--tasks-only` leaves the part out | the band asks with one call a minute, and "could not look" must not read as "nothing waits" there either |
| B127 | Band: while proposals wait, one row below the candidates says how many (`3 proposals from your sessions`), never one per proposal, and the task of B124 is no row of its own. `show` on that row and `/m2b-proposals`, which runs at once also during a turn, open the m2b pane with each proposal: its text, its kind with due day and topic, the person's words and the day they were said, keep and drop, and keep all while two or more can still be pressed. A press writes nothing for 5 seconds and offers undo, like a candidate's (B94); then `m2b proposals keep <id>` or `drop <id>` runs. Keep all names the ids the pane showed when it was pressed, without those pressed on their own, and never `--all`. After the write the band reads again, so row and pane show what still waits and how many answers wait for the next curation run, which files them. What `m2b` says to an answer it refuses, or cannot write, stands in the pane and in the band. After keep all, where another answer stands, that line names the first such proposal by its text, not all of them, and what could be kept is kept. Proposals that could not be looked at (B126), a part of another shape and an id the core would not make are one error line in both, never "none" and never a row to press; beside a task list that could not be read the band keeps to that one line; before the band's first answer about proposals the pane and the command say that m2b has not looked yet. Where no pane can be shown, the command answers as text: how many wait, how to list and answer them with `m2b proposals`, then the proposals with their ids as far as the 20 lines of such an answer reach; `show` says in the band that the pane cannot be shown. What the band says about a task is not drawn in the proposals pane | the proposals are answered together where the person works, a mis-click must not cost a proposal that does not come back for 90 days, and keep all must not keep a proposal that arrived unseen |
| B128 | Band: every text of a proposal it draws (the text, the person's words, kind, topic and days) is one line with white space as single spaces and each control character, format character and other character a terminal gives no width (by Unicode property: the marks that reorder text, zero-width characters, the byte order mark, soft hyphens, variation selectors, tag characters) written out (`\x1b`, `\u202e`), never left out as in the band's other rows (B95) and never sent to the terminal | keeping keeps the text as stored, so a part the drawing left out would be kept unseen (B122) |
| B154 | Band: `mcp__m2b__search` takes `question_language`, the language the question was asked in as the model names it, required by the tool's schema and no search term; where it reads as the name of a language (letters with their marks, spaces, apostrophes, brackets and hyphens, at most 40 characters, the characters that draw nothing taken out as in B143) the result ends with a line that says to answer in that language, also a result without hits; any other value adds nothing to the result | told only to answer in the question's language (B104 and the skill `search`), a model answered in the language of the notes about one time in six where the distillate and the notes were both in another; a model that names the language before it reads the notes and reads the name back after them kept to it |
